## Decisions

1. **One popup, wired per bar.** `StatHelp` (a full-screen `ColorRect` scrim with a `DialogPanel` card) is created once in `_build_runtime_ui()`. `_create_stat_bar()` is the only place that builds stat bars, and it calls `stat_help_popup.attach(row, stat_key, color)`, so every current and future stat bar gets the behaviour. No screen has its own copy.
2. **Tap detection.** The bar row uses `MOUSE_FILTER_PASS` and its children (icon, label, bar, value) ignore input, so a tap on any part counts. The popup opens on release, and only if the release is within 16 px of the press. A drag (scrolling the Level Up list) does not open it, and PASS lets the scroll container still receive the drag. Touch reaches this path through Godot's default touch-to-mouse emulation.
3. **Tap anywhere closes.** The scrim closes on press and accepts the event. The matching release is captured by the popup, so it cannot trigger a button underneath. Back closes it first (before any other modal), and `_activate_screen()` closes it on screen changes.
4. **Texts.** Name and description keys live in `StatHelp.STAT_TEXT_KEYS`. The static helpers `get_stat_name()` and `get_stat_description()` use `TranslationServer`, so the Level Up guide shows exactly the same wording. Numbers come from `CombatRules` constants. Monster bars use the same descriptions; the Life text also says what 0 life means for a monster.
5. **Level Up empty area.** A `CardPanel` "What each stat does" sits under the allocation rows, inside the existing scroll container. It is rebuilt with the rows, so the `+N per point` values follow the class growth from `CombatRules.get_stat_growth_for_player()`.

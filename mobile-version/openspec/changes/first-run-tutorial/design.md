## Decisions

1. **Trigger: first dungeon entry.** `start_dungeon_exploration()` calls `_show_first_run_tutorial_if_needed()` as its last step. The tutorial shows over the exploration view, so the grid, the arrows and the green entrance it describes are right behind it. Starting a game (the hub) does not trigger it: the hub has nothing the tutorial explains yet. A resumed run (Load Game) does not trigger it either, because it does not go through `start_dungeon_exploration()`.
2. **Flag storage: the settings file, not the save.** `SettingsStore.load_tutorial_seen()` / `save_tutorial_seen()` store `[tutorial] seen=true` in `settings.cfg` (the path comes from `main.settings_path`, so every test uses its own file). The tutorial is device knowledge, not character progress: starting a new game or losing the save must not show it again. `save_locale()` and `save_tutorial_seen()` now load the existing file before writing, so each keeps the other.
3. **Marked seen on close, not on open.** Skip, Done and Android back all mark it seen. If the app is killed while it is open, it shows again on the next dungeon entry.
4. **Overlay, not a screen.** The tutorial is a full-screen overlay (`scripts/tutorial.gd`) above the current screen, like the result modal. `_activate_screen()` hides it without marking it seen, so screen changes made from code (tests, the playtest bot) never leave it on top of another screen. Calls such as `_start_new_game()` and `start_dungeon_exploration()` keep working with the overlay open, so the bot and the existing tests are not blocked. The bot still skips it in `_settle()`, like a returning player would.
5. **Numbers from the rules.** Page bodies are format strings filled from `CombatRules` constants (`ENERGY_MOVE_COST`, `ENERGY_ATTACK_COST`, `ENERGY_QUEST_COST`, `ENERGY_RETREAT_COST`, `REST_MANA_COST`, rest, sanctuary and quest constants). Fleeing costs `ENERGY_MOVE_COST`, so the text uses that constant for the flee cost too.
6. **Layout.** One `DialogPanel` card with a fixed minimum height (460 logical px), so Next/Done stay in the same place on every page. The body label expands and wraps. At the 390x844 design viewport with `expand` stretch, 1440x3088 maps to 393x844 and 1080x2220 maps to 410x844 logical px. The test resizes the window to both and checks that the card and buttons fit in EN and ES.

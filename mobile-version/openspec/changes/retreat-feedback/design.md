## Decisions

1. **The Retreat reason has its own caption.** The feedback line under the map already holds the last action message and the Rest reason (DNG-16) in its two reserved lines. Away from the entrance the Retreat reason is almost always true, so adding it there would push the label to three lines and mix a permanent hint with short-lived messages. Instead a one-line `CaptionLabel` ("RetreatHint") sits right under the Rest / Retreat row, right-aligned below the Retreat button. It never wraps (long text is trimmed with an ellipsis) and keeps its height when empty, so the map cell size stays the same on and off the entrance. `_update_exploration_actions()` refreshes it together with the button, and `_apply_menu_text()` refreshes it on a language change.

2. **Same source of truth as the button.** `_get_retreat_block_hint()` uses the same check as the button (`current_location.type == ENTRANCE`), and returns "" outside a dungeon and while the run is ending. A `_retreat()` call away from the entrance no longer writes a feedback message: it only refreshes the actions, as `_rest()` does when blocked, so the reason is never shown twice.

3. **Reworded key.** `EXPLORE_RETREAT_ENTRANCE_ONLY` now reads "Return to the green entrance to retreat" / "Volvé a la entrada verde para retirarte". It says what to do, and "green" ties it to the tile colour. No other code used the old text.

4. **Entrance highlight without new art.** The entrance tile was already green. A light-green (`#a6f7bd`) 3 px ring, inset about 14 % of the cell, is drawn inside it. The inset keeps the gold player ring (4 px at the cell edge) visible when the player stands there, and the player marker is added after it, so it is drawn on top. No new icon was needed.

5. **Arrow to an entrance off the window.** `_get_entrance_arrow()` clamps the entrance coordinates into the visible window; when the clamped cell differs from the entrance, that edge (or corner) cell gets the existing `arrow_right.svg` tinted light green, rotated by `atan2(row delta, column delta)`. That covers the 8 directions with one icon, and the arrow moves along the edge as the player walks. When the entrance is in the window, nothing is drawn. A text hint ("2 up, 3 left") was considered and dropped: it would need another line and is harder to read than an arrow on the map.

6. **Summary from values read around the commit.** `_retreat()` reads `dungeon_experience` before `CombatRules.commit_dungeon_experience()` (which resets it) and passes it to `_format_retreat_summary()`, which runs after the commit so the total already includes it. The next threshold comes from `CombatRules.get_experience_threshold(level)` (experience is cumulative). Zero banked experience gets its own line instead of "+0". When the total already reaches the threshold the line points to Progression, where levels are converted, instead of showing a negative "more for level".

7. **Balance bot.** `tools/playtest_bot.gd` classified a retreat by comparing the whole result message with `RESULT_RETREATED_MESSAGE`. The message now has more lines, so it checks that the message starts with that line. Rules are unchanged, so `verify_balance.gd` thresholds are unchanged.
